MANUAL DE USO · v2.3.0

Agent Hub

Guía completa para gestionar tus agentes de IA, organizar proyectos y mantener contexto por proyecto. Incluye orquestaciones DAG con ejecución paralela, scripts determinísticos, gates HITL, skills por agente, servidores MCP y mucho más. Compatible con Claude, GitHub Copilot, Gemini, DeepSeek, Groq y cualquier proveedor compatible — todo desde una interfaz visual.

Construida con IA. Para la IA. Con manos humanas al volante.

Primeros pasos

Instalación

Agent Hub es un ejecutable portable. No requiere instalador ni Node.js en el sistema.

1
Descargar el ejecutable
Ve a la sección Releases del repositorio y descarga agent-hub.exe.
2
Elige una ubicación permanente
Mueve el .exe a la carpeta donde quieras que viva la app — por ejemplo C:\Tools\AgentHub\. Todos los datos (agentes, configuración, caché) se crean en esa misma carpeta.
3
Ejecuta el .exe
La primera vez arranca el wizard de configuración. En ejecuciones posteriores carga directamente la vista de Proyectos.
Portabilidad
Puedes mover toda la carpeta a otro lugar — la app funciona desde cualquier ubicación. Las rutas de los proyectos registrados son absolutas; si mueves los proyectos en disco, actualiza sus rutas desde la app.

La vista de inicio de Agent Hub. Centraliza en seis tarjetas el estado de tu ecosistema: métricas generales, sincronización, salud de proyectos, oportunidades de mejora, acciones rápidas y uso de IA. Se actualiza automáticamente cada 30 segundos.

Contadores de agentes desglosados por nivel (Global, Categoría y Sin categoría) y de proyectos por estado (Activos, Pausados, Archivados). Haz clic en la fila de Agentes o Proyectos para navegar directamente a esa vista.

Sincronización

Tres indicadores de estado: agentes pendientes de sync con tus proyectos, proyectos desactualizados y estado del directorio de agentes externo. El botón Sincronizar todo propaga todos los cambios pendientes a todos los proyectos de una vez. Incluye una nota de "Salud en vivo: actualización cada 30s".

Salud de Proyectos

Lista de hasta 6 proyectos activos con un dot indicator de color y el primer problema detectado. Muestra en qué estado está cada uno: ruta, contexto, sync y agentes. Botón "Ver todos" si hay más de 6.

Saludable
Sin incidencias. Ruta accesible, contexto editado, agentes sincronizados y sin prompts corruptos.
Advertencia
Sync desactualizado (más de 3 días), contexto demasiado corto o agentes sin herramientas configuradas.
Crítico
Ruta del proyecto no encontrada en disco, fichero de contexto ausente o agentes con frontmatter inválido.

Oportunidades de Mejora

Agent Hub analiza proyectos y agentes y genera recomendaciones accionables. Por defecto se muestran 5; el botón Ver todas las expande. Tres tipos de notificación:

CRÍTICA
Fichero de contexto completamente ausente (CLAUDE.md, copilot-instructions.md…). Acción: abrir el generador de contexto.
MEJORA
Contexto existente pero con menos de 80 caracteres, agente sin herramientas o con system prompt sin optimizar. Acción: abrir el editor o el optimizador.
INFO
Agentes pendientes de sync en un proyecto concreto. Acción: abrir la vista de proyectos o forzar el sync.
Descartar y aplazar
Cada notificación tiene un botón de acción directo y dos opciones de gestión: Descartar (la oculta permanentemente) y Aplazar (la oculta 7 días). El contador de ocultas del topbar diferencia entre descartadas y aplazadas. El botón Restaurar deshace ambas.
Navegación directa a agentes
Al hacer clic en una notificación de tipo agente, la app navega a la vista de Agentes, expande los nodos del árbol necesarios y abre el editor del agente afectado directamente.

La aplicación

Skills

Las skills son bloques de contexto tecnológico que Agent Hub inyecta automáticamente en el system prompt de un agente cuando se ejecuta en un proyecto que las tiene configuradas. Sustituyen al antiguo nivel "Tecnología" de la jerarquía.

Por qué skills en lugar de agentes por tecnología
Un agente como front-coder sabe implementar componentes UI, pero no conoce los detalles de tu stack concreto. La skill react le aporta ese contexto: React 18 con hooks, estado con Zustand, estilos con TailwindCSS… El agente se mantiene genérico y las skills aportan la especificidad. Puedes combinar varias skills por proyecto.

Cómo funciona la inyección

Cuando ejecutas un agente sobre un proyecto (desde el panel de ejecución, una orquestación o el Subsistema CLI), Agent Hub también inyecta las skills configuradas en el propio agente (campo skills[] del frontmatter para agentes de proyecto). La secuencia es:

1
Lee las skills del proyecto
Lee el array skills[] del proyecto (ej: ["react", "tailwind", "typescript"]).
2
Carga los bloques de contenido
Lee el contenido Markdown de cada fichero agents/skills/{nombre}.md.
3
Concatena al system prompt
Añade el bloque de cada skill al final del system prompt del agente antes de llamar a la IA. El agente "ve" el contexto tecnológico como parte de sus instrucciones.

Los agentes creados directamente en un proyecto (nivel 4) pueden tener sus propias skills asociadas, independientes de las skills del proyecto. Se configuran en el campo Skills asociadas del editor de agente — visible solo cuando el agente es de nivel proyecto.

Dos capas de skills
Cuando ejecutas un agente de proyecto, se inyectan primero las skills del proyecto y después las skills propias del agente. Esto permite skills generales del proyecto (React, TypeScript) y skills especializadas por agente (por ejemplo, una skill de convenciones de testing solo para el agente test-writer).

La aplicación

Vista Orquestaciones

Crea y ejecuta workflows de múltiples agentes en paralelo y en secuencia sobre tu proyecto mediante un modelo DAG (grafo dirigido acíclico). Los nodos sin dependencias entre sí se ejecutan simultáneamente, con control granular del flujo de datos entre pasos, contexto estático y dinámico, gates HITL, rollback paso a paso y auditoría completa.

Por qué es la función más potente de Agent Hub
Un agente solo puede hacer una cosa a la vez. Las orquestaciones encadenan agentes en un pipeline inteligente con ejecución paralela: el reviewer y el security-auditor analizan a la vez, el refactorizador actúa sobre ambos análisis, el test-writer genera tests para los cambios. Todo automático, con los ficheros reales del proyecto como base de trabajo.
screenshots/06-orchestrations.png Vista principal de orquestaciones — listado de cards por proyecto

Conceptos clave

DAG — Grafo de nodos
La orquestación es un grafo dirigido acíclico. Cada nodo declara de qué nodos depende (dependsOn). Los nodos sin dependencias entre sí se ejecutan en paralelo (Promise.allSettled). Los nodos dependientes esperan a que sus predecesores terminen.
Arista (conexión)
El enlace entre dos nodos del grafo. Se representa como una curva SVG en el lienzo. Al hacer clic en el punto central de la arista, el panel derecho muestra el configurador de DataFlow, contexto y gate HITL.
Contexto fijo
Texto libre o ficheros del proyecto que se incluyen siempre en un nodo concreto, independientemente de lo que haya ocurrido antes. Se configura una sola vez al editar la orquestación.
Contexto temporal
Campos dinámicos (texto o fichero) que Agent Hub solicita al usuario justo antes de cada ejecución. Útil para pasar un ticket, un mensaje de commit o una rama como contexto fresco en cada run.

Lista de orquestaciones

Al entrar en la vista Orquestaciones, ves las tarjetas de todas las orquestaciones del proyecto seleccionado en el topbar. Cada tarjeta muestra: nombre, descripción, estado de la última ejecución, número total de ejecuciones y fecha de la última.

La última ejecución completó todos los pasos sin errores.

Algunos pasos se completaron pero hubo errores. Los pasos exitosos no se revierten.

Las acciones de cada tarjeta son: Editar (abre el editor visual), Ejecutar (abre el panel de ejecución directamente) y Eliminar (con confirmación modal — borra el JSON de la orquestación pero no el historial de ejecuciones).

DataFlow — qué se pasa entre agentes

En cada conexión defines exactamente qué información del agente anterior recibe el siguiente. Activa o desactiva cada canal con un checkbox en el configurador:

Output del agente anterior
El texto completo de respuesta que generó el agente anterior. Es el canal más habitual: el reviewer escribe su análisis y el refactorizador lo lee como punto de partida.
Ficheros modificados
Lista de rutas de todos los ficheros que el paso anterior creó o modificó. El agente receptor los recibe en su contexto para trabajar sobre ellos. El contenido lo puede solicitar vía herramientas.
El contexto del proyecto lo gestiona el propio agente
El checkbox de CLAUDE.md fue eliminado del DataFlow. Si un agente necesita las reglas del proyecto, debe declararlo en su system prompt e incluir la herramienta Read para leer el fichero directamente en tiempo de ejecución.
Al menos un canal debe estar activo
La validación previa a la ejecución rechaza conexiones donde ningún canal de DataFlow está activado: el agente receptor no tendría ningún contexto relevante del paso anterior y ejecutaría "en vacío".

Contexto fijo y contexto temporal

Además del DataFlow, cada conexión puede incluir contexto adicional que se suma al mensaje del agente receptor.

Contexto fijo

Se configura en el editor y siempre se incluye en esa conexión:

  • Texto libre — reglas adicionales, instrucciones extra, un fragmento de código de referencia.
  • Ficheros del proyecto — rutas absolutas o relativas que se leen en tiempo de ejecución. Selecciona con el selector de fichero nativo ().
Contexto temporal

Campos que Agent Hub pide al usuario cada vez que se ejecuta la orquestación:

  • Tipo texto — campo libre para introducir cualquier valor en cada run (mensaje de PR, número de ticket, rama de referencia…).
  • Tipo fichero — selector de fichero que se abre al inicio de cada ejecución.

Los campos marcados como requeridos bloquean el inicio de la ejecución si están vacíos.

Configuración de ejecución

Aparece en la parte inferior del panel configurador al seleccionar cualquier conexión. Aplica a toda la orquestación:

stopOnError
Si está activo (defecto: sí), la ejecución se detiene en el primer paso que falle. Si está desactivado, continúa con los pasos siguientes aunque alguno haya fallado.
maxTurns
Máximo de turnos del Subsistema CLI por paso (defecto: 10). Aumenta este valor si tus agentes necesitan muchas iteraciones para completar su tarea.
timeout
Tiempo máximo global de toda la orquestación en milisegundos (defecto: 300 000 ms = 5 min). El tiempo restante se reparte entre los pasos. El tiempo de pausa en gates HITL no descuenta.

Si está activo, ejecuta validate-output tras cada paso IA. Si la validación falla, el paso se marca como advertencia. Útil para detectar outputs malformados sin detener la ejecución.
maxContextChars
Límite de caracteres del mensaje de usuario en cada paso (defecto: 4 000). Si el contexto ensamblado supera este límite, se trunca con un aviso visible en el log. Aumenta este valor si usas modelos con ventana de contexto grande.

Toggle en el panel configurador de cada conexión. Cuando está activo, la ejecución se pausa tras el agente que precede a esa conexión para revisión humana. Ver sección Gates HITL.

Rollback granular

Antes de ejecutar la orquestación, Agent Hub toma un snapshot del estado del filesystem del proyecto (hasta 500 ficheros de texto, máx. 256 KB por fichero). Este snapshot se guarda en:

{ruta-del-proyecto}/
└── .agent-hub/
└── executions/
└── {timestamp}-{orchId}/
├── result.json ← resultado completo de la ejecución
└── snapshot.json ← contenido previo del filesystem

Desde el resultado final puedes hacer rollback de cualquier paso individual pulsando el botón correspondiente en su tarjeta. El rollback restaura solo los ficheros que ese paso modificó, sin tocar lo que hicieron los demás pasos.

Historial de ejecuciones
Cada ejecución queda registrada. Puedes ver el historial completo de una orquestación desde su tarjeta en el listado. El historial incluye fecha, duración, estado y el detalle completo de cada paso con posibilidad de rollback posterior.

Reanudar ejecuciones interrumpidas

Si una ejecución se interrumpió a mitad (error de red, cierre de la app, timeout parcial), Agent Hub permite reanudarla desde el paso donde se detuvo. Los pasos ya completados no se re-ejecutan — se cargan desde el estado guardado y la ejecución continúa desde el punto de interrupción.

Cómo reanudar
En el historial de ejecuciones, las ejecuciones interrumpidas muestran el botón Reanudar. Al pulsarlo, el sistema carga el estado guardado en execution-state.json y continúa la ejecución desde el paso siguiente al último completado.
Estado de ejecución guardado
Tras cada paso completado se persiste en .agent-hub/executions/{id}/execution-state.json: el índice del último paso completado, el estado de cada paso y los ficheros modificados. Este estado es la base para la reanudación.

Validación previa

Antes de lanzar cualquier ejecución, Agent Hub valida la orquestación. Si hay errores, los muestra en un banner coral y bloquea el inicio. Las comprobaciones son:

  • Al menos 2 agentes en la orquestación
  • Todos los agentes existen en disco
  • Número de nodos = agentes − 1
  • Índices from/to consecutivos y válidos
  • Cada conexión tiene al menos un canal de DataFlow activo
  • Los ficheros de contexto fijo existen en disco
  • El directorio del proyecto existe
  • timeout ≥ 5 000 ms

Casos de uso habituales

Review ∥ Security → Refactor → Tests
El reviewer y el security-auditor analizan en paralelo. El refactorizador actúa sobre ambos análisis. El test-writer genera tests para los cambios. Ejecución en 3 niveles topológicos: {reviewer, security-auditor} → refactor → test-writer.
Review → Refactor → Tests (secuencial)
El reviewer analiza, el refactorizador aplica mejoras, el test-writer genera tests. Modelo lineal clásico. DataFlow: output + ficheros modificados en ambas conexiones.
Security Audit → Fix
El auditor identifica vulnerabilidades con referencias a rutas concretas. El fixer aplica los patches sobre esas rutas. Contexto temporal: rama o versión del código a auditar.
Análisis → Documentación
El analizador extrae firmas, exportaciones y comentarios. El doc-writer genera el fichero de documentación. Contexto fijo en la segunda conexión: plantilla de formato que se debe usar.
Debug → Fix → Validate
El debugger localiza la causa raíz de un bug. El fixer lo corrige. El validador ejecuta los tests y confirma la reparación. Contexto temporal en el primer paso: descripción del bug o fragmento de log.
Refactor incremental
Varias pasadas de refactorización con agentes especializados: primero renombrado y estructura, luego rendimiento, luego eliminación de código muerto. Cada paso recibe los ficheros del anterior como punto de partida.
Onboarding automático
El analizador lee el proyecto y produce un resumen. El doc-writer genera el CLAUDE.md o README inicial. Contexto temporal: nombre del equipo o tech lead al que va dirigida la documentación.
Funciona con cualquier proveedor de IA
El orquestador usa el Subsistema CLI para que los proveedores API Anthropic y GitHub Copilot puedan operar directamente sobre el filesystem del proyecto (leer, escribir, buscar ficheros) con las mismas capacidades que Claude CLI nativo. No necesitas tener la CLI instalada para ejecutar orquestaciones si usas API key o GitHub Copilot.

Automatización de navegador (CDP)

Si algún agente de la orquestación incluye herramientas con prefijo browser_*, Agent Hub activa el modo CDP (Chrome DevTools Protocol). Antes de ejecutar, el formulario previo muestra la sección de navegador:

browser_get
Navega a una URL y extrae texto o HTML. Puede esperar a un selector concreto antes de capturar el contenido.
browser_action
Interactúa con el DOM: click, rellenar un campo, seleccionar, hover, evaluar un script o esperar.
browser_screenshot
Captura de pantalla de la página o de un elemento concreto. Devuelve imagen en base64.
El navegador debe estar conectado antes de ejecutar
Agent Hub lanza un navegador dedicado con un perfil de usuario separado (~/.agent-hub-cdp-profile) y puerto CDP propio. Puedes hacer login manualmente en ese navegador antes de pulsar Continuar para que la sesión esté disponible para el agente. Navegadores soportados: Chrome, Edge, Brave y Firefox.
Las orquestaciones consumen más tiempo y tokens que un agente solo
Cada paso es una ejecución completa de un agente con acceso al filesystem. Una orquestación de 3 agentes con maxTurns: 10 puede suponer hasta 30 turnos de IA en total. Ajusta maxTurns y timeout según la complejidad real de cada paso para no exceder límites de tu proveedor.

Scripts determinísticos y personalizados

Los scripts son nodos especiales de una orquestación que ejecutan lógica Node.js predefinida sin llamar a la IA. Son instantáneos, reproducibles y no consumen tokens. Se identifican por el prefijo __script: y aparecen en el lienzo con un badge azul script. Existen dos tipos: built-in (incluidos con Agent Hub) y externos (creados por el usuario en la carpeta user-scripts/).

Para qué sirven
Intercalar un script entre dos agentes IA permite pasar contexto estructurado, validar outputs o calcular métricas sin gastar tokens. Por ejemplo: analizar el proyecto antes del primer agente, validar que el output es JSON válido antes del segundo, o puntuar la calidad del paso anterior.

Scripts disponibles

prepare-context
Analiza el proyecto: detecta lenguaje principal, framework, tests y convenciones. Guarda el resultado en .agent-hub/context/canonical.json y lo pasa al siguiente agente como contexto estructurado.
generate-file-index
Lista todos los archivos del proyecto con tamaño, extensión y fecha de modificación. Útil para que el siguiente agente tenga un mapa del proyecto sin necesitar leerlo por su cuenta.
diff-since-step
Compara el estado actual del filesystem con el del paso de referencia y devuelve la lista de archivos modificados. Permite que el siguiente agente trabaje solo sobre lo que cambió.
validate-json
Verifica que el output del agente anterior es JSON sintácticamente válido. Si no lo es, devuelve el error de parsing para que el siguiente paso pueda corregirlo o la orquestación se detenga.
quality-score
Calcula una puntuación 0–100 del paso anterior sin llamar a la IA: respuesta producida, JSON válido, archivos modificados, longitud sustancial. Devuelve el score y un grade verde/ámbar/rojo.
validate-output
Valida el output del agente anterior según reglas configurables. Devuelve { passed, issues[] } para que el siguiente paso o la lógica de stopOnError actúe en consecuencia.
budget-guard
Requiere el parámetro maxBudgetUSD (configurable en el configurador de conexión). Suma el coste estimado de todos los pasos anteriores y detiene la orquestación si el total supera el límite. El panel muestra un banner coral de presupuesto agotado.

Scripts personalizados

Además de los scripts built-in, puedes crear tus propios scripts Node.js y colocarlos en {carpeta-de-Agent-Hub}/user-scripts/. Se cargan en caliente sin reiniciar la app y aparecen en la paleta bajo la tab Scripts personalizados con un badge diferenciado.

// user-scripts/mi-script.js
exports.label = 'Mi script';
exports.description = 'Descripción breve';
exports.run = async ({ projectPath, prevResult, fs, path }) => {
const content = await fs.readFile('README.md');
return { output: content.slice(0, 500), filesModified: [], data: {} };
};
API de filesystem disponible en scripts
Los scripts externos reciben una API fs sandboxed: readFile, writeFile, exists, listDir, readJSON, writeJSON. Todas las rutas son relativas al projectPath. Las rutas con .. que escapan del proyecto lanzan un error de seguridad.

Cómo añadir un script al workflow

1
Cambia a la tab "Scripts" en la paleta
En el panel izquierdo del editor de orquestaciones hay dos tabs: Agentes y Scripts. La tab Scripts muestra los scripts built-in en la primera sección y los personalizados en la segunda. Los scripts externos con parámetros mal configurados muestran un icono ámbar de aviso.
2
Arrastra el script al lienzo
El script aparece como un nodo con fondo azul claro y el badge script. Puedes colocarlo antes o después de cualquier agente IA en el flujo.
3
Configura las conexiones como con cualquier agente
Las conexiones de entrada y salida del script se configuran igual que entre agentes. El output del script ({ output, filesModified, data }) se pasa al siguiente nodo como "salida del paso anterior".
Los scripts no consumen tokens ni requieren proveedor de IA
Son puro Node.js. Funcionan con cualquier proveedor configurado (CLI, API, GitHub Copilot…) y su duración es típicamente menor a 1 segundo. No se limitan por maxTurns ni timeout de la IA.

Gates HITL

Los gates Human In The Loop son puntos de control opcionales entre pasos de una orquestación. Cuando un gate está activo, la ejecución se pausa tras ese paso y espera una decisión del operador antes de continuar.

Por qué son útiles
En workflows de alto impacto (escribir código de producción, modificar ficheros críticos, enviar comunicaciones), no siempre quieres que la ejecución avance automáticamente. Con un gate puedes revisar lo que hizo el agente, aprobar si está bien o pedirle que lo rehaga con feedback antes de seguir.

Activar un gate en el configurador

Al editar una conexión en el panel configurador derecho, al final de la sección aparece el toggle Gate de revisión humana. Al activarlo, la ejecución se detendrá después del agente que precede a esa conexión.

Agent Hub · Gate HITL activo
Paso 2 completado — revisión requerida

El agente code-refactor ha terminado. Revisa los cambios antes de continuar con el siguiente paso.

Las tres decisiones del gate

Aprobar y continuar
La ejecución avanza al paso siguiente. Los cambios del paso actual quedan en disco.
Revisar y rehacer
Los cambios del paso se revierten al snapshot pre-paso. Se abre un campo de texto para escribir el feedback, y el agente se re-ejecuta con ese feedback añadido a su prompt. El tiempo de pausa no descuenta del timeout global.
Cancelar orquestación
La ejecución se detiene aquí. Los cambios de pasos anteriores permanecen a menos que hagas rollback manual desde el historial.
El tiempo de espera del gate no consume timeout
Cuando la orquestación está pausada en un gate, el reloj global del timeout se detiene. El tiempo que tardas en revisar y decidir se descuenta al reanudar, así que no hay prisa y el siguiente paso tiene todo su tiempo disponible.

Quality Score

Tras completar cada paso IA de una orquestación, Agent Hub calcula automáticamente un Quality Score sin llamar a la IA. Es un indicador rápido de si el agente produjo un output razonable.

Cómo se calcula

Checks evaluados
  • El agente produjo alguna respuesta (no vacío)
  • Si el output parece JSON, es JSON válido
  • Si la tarea implicaba escribir archivos, se modificó al menos uno
  • La respuesta tiene más de 100 caracteres (sustancial)
Puntuación y grades

La puntuación es (checks superados / total checks) × 100.

verde≥ 75 / 100
ámbar50 – 74 / 100
rojo< 50 / 100

Dónde aparece

En el panel de ejecución, la tarjeta de resultado de cada paso muestra un badge QS 85/100. Al hacer clic en el badge se expanden los checks individuales con su estado. El Quality Score también queda registrado en el result.json de la ejecución.

El Quality Score no bloquea la ejecución
Es solo un indicador visual. Si quieres detener la ejecución cuando la calidad es baja, combina el script quality-score como paso explícito en el workflow con stopOnError activo y un agente posterior que interprete el resultado.

Git Checkpointer

Cuando un proyecto tiene gitEnabled: true y es un repositorio git, Agent Hub realiza un commit automático tras cada paso completado de una orquestación. Esto permite rollback exacto a cualquier punto de la ejecución usando la historia git del proyecto.

Activar el checkpointer

Abre el drawer del proyecto, ve al footer y pulsa Editar. En el modal de edición encontrarás el toggle Git Checkpointing. El proyecto debe ser un repositorio git (debe existir .git/ en la raíz).

# Commits generados automáticamente tras cada paso
AgentHub [orchName] paso 1/3: "code-reviewer"
AgentHub [orchName] paso 2/3: "refactor"
AgentHub [orchName] paso 3/3: "test-writer"
Rollback vía git
Si el rollback git está disponible (hay SHA del commit anterior), Agent Hub usa git reset --hard {sha} para restaurar exactamente el estado de ese paso. Más preciso que el snapshot de ficheros, ya que preserva también metadatos y permisos.
Fallback por snapshot
Si el checkpointing git no está activo o no hay SHA disponible, el rollback usa el snapshot de ficheros JSON (siempre disponible como respaldo). Ambos mecanismos coexisten.
Los commits se hacen con git add -A
El checkpointer hace stage de todos los cambios del directorio de trabajo antes de cada commit. Si tienes cambios no relacionados en staging o en el worktree, también se incluirán en el commit del checkpoint. Usa el checkpointer solo en proyectos donde no estés trabajando activamente en paralelo.

Ops Ledger

El Ops Ledger es un registro append-only de cada operación atómica (modificación de fichero) realizada por una orquestación. Es la bitácora de qué cambió, cuándo y qué agente lo hizo. Persiste en {proyecto}/.agent-hub/ops/{orchId}-ledger.json.

Qué registra el ledger

  • ID único por operación (op-{hex})
  • executionId y orchestrationId vinculados
  • stepIndex y nombre del agente que lo hizo
  • filePath del archivo modificado
  • status: applied o reverted
  • timestamps de creación y reversión

Acceder al ledger desde la UI

En el panel de ejecución (resultado final), las tarjetas de cada paso tienen una pestaña Ops que muestra las operaciones atómicas de ese paso. Puedes revertir operaciones individuales pulsando el botón de revertir en cada entrada.

Ledger acumulativo por orquestación
El ledger es acumulativo: cada vez que ejecutas la misma orquestación, las nuevas operaciones se añaden al mismo fichero. Esto permite rastrear el historial completo de cambios de toda la vida de esa orquestación, no solo de la última ejecución. El endpoint GET /api/orchestrations/:id/ops devuelve el ledger completo.

MCP — Herramientas externas

Model Context Protocol (MCP) es el estándar de Anthropic para conectar agentes de IA con herramientas y fuentes de datos externas mediante JSON-RPC 2.0. Con MCP, cualquier agente de Agent Hub puede usar herramientas de GitHub, Linear, PostgreSQL, Slack y decenas de servicios más — sin tocar el código de la app. Se configura desde Ajustes → MCP.

Por qué usar MCP

Herramientas tipadas
El agente llama a create_issue, list_prs o query con parámetros validados — no improvisa sintaxis de bash.
Sin cambios de código
Añades un servidor MCP desde la UI y está disponible para todos los agentes. Sin reiniciar, sin tocar ficheros de configuración manualmente.
Ecosistema creciente
GitHub, Linear, Notion, Jira, Slack, PostgreSQL, SQLite, Brave Search… Decenas de servidores MCP listos para usar.

Servidores sin credenciales (preinstalados)

Tres servidores se activan automáticamente en el primer arranque de la app. No requieren configuración:

fetch
Descarga el contenido de cualquier URL y lo devuelve al agente. Útil con proveedores API/GitHub que no tienen acceso nativo a la web.
memory
Almacenamiento clave-valor persistente entre ejecuciones distintas del mismo agente. El agente puede «recordar» hechos entre sesiones.
sequential-thinking
Fuerza al modelo a descomponer el problema antes de responder. Mejora la calidad en tareas analíticas complejas.

Catálogo de servidores con credenciales

Desde Ajustes → MCP → Catálogo → Con credenciales puedes añadir estos servidores rellenando solo tus credenciales — el comando, los args y la estructura de variables de entorno ya están preconfigurados:

github
Repositorios, issues, PRs, ramas y releases de GitHub.
jira
Proyectos, tickets y sprints de Jira Cloud.
postgres
Consultas SQL sobre una base de datos PostgreSQL.
sqlite
Consultas sobre una base de datos SQLite local.
brave-search
Búsqueda web y de noticias en tiempo real vía Brave Search API.
slack
Envío y lectura de mensajes en canales de Slack.

Variables de entorno y credenciales

Agent Hub usa el formato $env:NOMBRE_VARIABLE para referencias a variables de entorno. Los valores reales nunca se almacenan en config.json — solo la referencia. Se resuelven en tiempo de ejecución desde el entorno del sistema operativo.

# En el campo Variables de entorno del servidor:
GITHUB_TOKEN=$env:GITHUB_TOKEN
# Agent Hub sustituye $env:GITHUB_TOKEN por el valor real al arrancar el servidor
Reinicia la app tras definir variables de entorno
Las variables de entorno del sistema operativo se leen cuando Electron arranca. Si defines una variable mientras la app ya está abierta, debes reiniciar Agent Hub para que el proceso la detecte.

Servidores globales vs. de proyecto

Globales
Disponibles en todos los proyectos y agentes. Ideales para herramientas transversales: fetch, memory, tu instancia de Linear o Jira corporativo.
De proyecto
Solo para ese proyecto. Útiles cuando distintos proyectos necesitan el mismo tipo de servidor con credenciales diferentes: p.ej. dos instancias de postgres apuntando a BDs distintas.

Asociar un servidor MCP a un agente

1
Configura el servidor en Ajustes → MCP
Añade el servidor desde el catálogo o manualmente. Prueba la conexión con el botón Probar conexión — si la respuesta muestra las herramientas disponibles, el servidor está listo.
2
Abre el editor del agente
En la sección Servidores MCP, usa el selector para añadir los servidores que el agente puede usar. Se guardan como chips eliminables. Disponible en agentes de cualquier nivel.
3
El agente tiene acceso a las herramientas
Al ejecutar el agente (standalone o en orquestación), Agent Hub arranca los procesos MCP necesarios antes del primer turno. El agente llama a las herramientas MCP igual que a las herramientas nativas. El badge en la card del agente confirma que tiene servidores MCP asociados.

Comportamiento por proveedor

Proveedor CLI nativo (claude)
Agent Hub escribe {proyecto}/.claude/settings.json con los servidores MCP del agente antes de cada spawn. El CLI los activa automáticamente — sin intervención adicional.
Proveedores API / GitHub / Custom
Las herramientas MCP se inyectan en el system prompt con su formato de invocación. El subsistema CLI multi-turno intercepta las llamadas y las ejecuta. Funciona con todos los modelos de alta capacidad.
gemini-cli
Agent Hub sincroniza la configuración en ~/.gemini/settings.json con el mismo formato que Claude CLI.
En orquestaciones
El orquestador adquiere los procesos MCP antes de ejecutar cada paso y los libera al terminar. Un pool de 30 s evita el cold start entre pasos consecutivos que usen los mismos servidores.

La aplicación

Jerarquía de niveles

Los agentes se organizan en cuatro niveles. Los tres primeros participan en el sistema de sync; el cuarto es exclusivo del proyecto.

1
Global
Aplica a todos los proyectos sin excepción. Si tienes Claude Code instalado, estos agentes también se sincronizan automáticamente a ~/.claude/agents/ para que estén disponibles en cualquier directorio desde la CLI, aunque el proyecto no esté registrado en Agent Hub.
2
Categoría
Aplica a todos los proyectos de esa categoría (Juegos, Frontend, Mobile, DevOps…). Útil para agentes específicos del dominio pero no de una tecnología concreta. La especificidad tecnológica se gestiona ahora con skills.
3
Sin categoría
Agentes descargados del Directorio externo que no encajan en ninguna carpeta estándar. Aparecen en la sección "Sin categoría" del árbol. Puedes editarlos y moverlos a cualquier nivel.
4
Proyecto
Exclusivo de ese proyecto. Se crea y edita desde el árbol seleccionando el proyecto, o directamente desde el drawer. Nunca participa en el sistema de sync — Agent Hub no lo toca al sincronizar.

Referencia

Preguntas frecuentes

¿Necesito tener Claude Code instalado?
No. Agent Hub es compatible con cualquier proveedor de IA: Claude Code CLI, Gemini CLI, Aider, Cline, Goose, API de Anthropic, GitHub Copilot, DeepSeek, Groq, OpenRouter y proveedores personalizados. Si tienes un CLI instalado, se usa directamente. Si usas una API, el Subsistema CLI interno emula las mismas capacidades de acceso al filesystem sin necesitar ningún CLI en el sistema.
¿Puedo usar Agent Hub sin configurar ningún proveedor de IA?
Sí. El modo manual siempre está disponible: puedes crear, editar, organizar y sincronizar agentes sin ningún proveedor. Solo las funciones de generación de system prompts, optimización, sugerencias, chat y generación de contexto requieren un proveedor configurado.
¿Los agentes se sincronizan automáticamente cuando los modifico?
No. Agent Hub marca los proyectos afectados con el badge de actualizaciones pendientes, pero tú decides cuándo aplicar el sync. Esto evita que cambios en los agentes lleguen a tus proyectos mientras estás trabajando en ellos.
¿Qué pasa si borro un agente de nivel global?
El fichero se elimina de agents/global/ en Agent Hub y de ~/.claude/agents/ (si aplica). En los proyectos que ya tenían ese agente copiado, la copia local queda intacta hasta que ejecutes un sync explícito.
¿Cuál es la diferencia entre "excluir y eliminar" y "solo excluir"?
"Excluir y eliminar" borra el fichero .md del directorio de agentes del proyecto (p. ej. .claude/agents/ o .github/agents/). "Solo excluir" mantiene el fichero en disco pero Agent Hub lo ignora en syncs futuros — el agente sigue disponible para el asistente de IA hasta que lo borres manualmente.
¿Puedo mover la carpeta del .exe a otro lugar?
Sí, Agent Hub es completamente portable. Mueve toda la carpeta (con config.json, agents/ y cache/) al nuevo lugar y ejecuta el .exe. Las rutas de los proyectos son absolutas — si también mueves los proyectos, actualiza sus rutas desde la app.
¿El auto-update funciona con el .exe portable?
Sí. electron-updater soporta portables. Al instalar la actualización, reemplaza el .exe existente con el nuevo. Tus datos (config.json, agents/, cache/) no se tocan — están junto al .exe, no dentro de él.
¿Qué diferencia hay entre "Nuevo proyecto" e "Importar"?
Nuevo proyecto crea la carpeta en el sistema de ficheros desde cero. Importar registra una carpeta que ya existe — útil para proyectos que ya tienes en disco y quieres empezar a gestionar con Agent Hub.
¿Con qué proveedores de IA funciona Agent Hub?
Con todos los configurados en Ajustes: CLIs nativos (Claude Code, Gemini CLI, Codex, Aider, Cline, Goose), APIs directas (Anthropic, GitHub Copilot, OpenAI, Gemini API, Mistral, DeepSeek, Groq, OpenRouter, Perplexity) y proveedores personalizados (Azure OpenAI, GAIA, cualquier endpoint compatible). No necesitas instalar ningún CLI si usas un proveedor API.
¿Funciona en macOS o Linux?
La app está desarrollada y probada en Windows 10/11. Electron es multiplataforma, pero el build actual genera solo .exe. Con ajustes en electron-builder.yml podría compilarse para macOS (.dmg) o Linux (.AppImage).
¿Necesito Claude CLI instalada para ejecutar orquestaciones?
No. El Subsistema CLI de Agent Hub emula las capacidades del CLI para cualquier proveedor API (Anthropic, GitHub Copilot, nativos OpenAI-compatible, Custom…). Puedes ejecutar orquestaciones completas con acceso al filesystem del proyecto con cualquier proveedor. Si usas Claude CLI, se usa el proceso nativo directamente.
¿Qué ocurre si un agente de una orquestación falla?
Si stopOnError está activo (por defecto), la ejecución se detiene y se ofrece el rollback del paso fallido y todos los posteriores. Si está desactivado, el orquestador continua con el siguiente paso marcando el fallido como advertencia.
¿Las orquestaciones modifican los ficheros del proyecto directamente?
Sí. Los agentes ejecutados en una orquestación tienen acceso real al filesystem del proyecto via la API-FS. Cada paso hace un backup automático antes de ejecutarse, por lo que puedes revertir cualquier cambio desde el historial de ejecuciones.
¿Qué es un script determinístico y cuándo usarlo?
Un script determinístico es un nodo de orquestación que ejecuta lógica Node.js predefinida sin llamar a la IA. No consume tokens y tarda menos de 1 segundo. Úsalos para: analizar el proyecto antes del primer agente (prepare-context), validar que el output del agente anterior es JSON válido (validate-json), calcular una puntuación de calidad (quality-score), o generar un índice de ficheros para dar contexto estructurado al siguiente agente.
¿Qué hace un gate HITL exactamente?
Un gate HITL (Human In The Loop) pausa la orquestación tras el paso marcado y espera una decisión manual. Puedes Aprobar (la ejecución continúa), Revisar y rehacer (los cambios de ese paso se revierten, escribes feedback y el agente se re-ejecuta con ese feedback), o Cancelar. El tiempo de espera en el gate no descuenta del timeout global de la orquestación.
¿Puedo reanudar una orquestación que falló a la mitad?
Sí. Agent Hub guarda el estado de ejecución tras cada paso completado en .agent-hub/executions/{id}/execution-state.json. Desde el historial de ejecuciones puedes pulsar Reanudar en cualquier ejecución interrumpida. Los pasos ya completados se cargan del estado guardado y la ejecución continúa desde el punto de interrupción.
¿Para qué sirve el Git Checkpointer en orquestaciones?
Cuando activas gitEnabled en un proyecto que es un repo git, Agent Hub hace un commit automático tras cada paso de la orquestación. Esto permite rollback exacto usando git reset --hard al SHA del commit anterior, más preciso que el snapshot de ficheros. Actívalo en el modal de edición del proyecto.
¿Cómo funciona la ejecución paralela en el DAG?
El motor calcula los niveles topológicos del grafo al inicio de la ejecución. Cada nivel agrupa los nodos cuyos predecesores ya han terminado. Los nodos de un mismo nivel se lanzan simultáneamente con Promise.allSettled — si alguno falla, los demás del nivel continúan. Una vez todos terminan, el motor avanza al nivel siguiente. El panel de ejecución muestra el bloque "Nivel N/M [K en paralelo]" con el estado de cada nodo en tiempo real.
¿Cómo conecto nodos para que se ejecuten en paralelo?
Para ejecución paralela, conecta múltiples nodos al mismo nodo predecesor (o al Orquestador). Por ejemplo: Orquestador → code-reviewer y Orquestador → security-auditor ejecutarán ambos a la vez. Luego conecta code-reviewer y security-auditor → refactor-agent para que espere a ambos antes de empezar. Arrastra desde el port inferior de un nodo hasta el port superior de otro para crear la conexión.
¿Qué son las "Skills asociadas" en un agente de proyecto?
Los agentes de nivel proyecto pueden tener sus propias skills además de las del proyecto. Se configuran en el campo Skills asociadas del editor de agente (visible solo para agentes de proyecto). Cuando se ejecuta el agente, se inyectan primero las skills del proyecto y luego las del agente. Es útil para dar a un agente específico (como test-writer) contexto adicional de convenciones de testing sin aplicarlo a todos los agentes del proyecto.
¿Cómo creo mis propios scripts determinísticos?
Crea un fichero .js CommonJS en la carpeta user-scripts/ junto al ejecutable de Agent Hub. Debe exportar exports.label, exports.description y exports.run = async (context) => ({ output, filesModified, data }). La app los carga en caliente — no necesitas reiniciarla. Aparecen en la paleta bajo "Scripts personalizados". Un script externo con el mismo nombre que un built-in es ignorado.
¿Para qué sirve el script budget-guard?
El script budget-guard suma el coste estimado (en USD) de todos los pasos anteriores y detiene la orquestación si supera el límite configurado. Añádelo como nodo entre pasos y configura el parámetro maxBudgetUSD en el panel configurador. Si se alcanza el límite, el panel muestra un banner coral de "presupuesto agotado" y la ejecución se cancela limpiamente. Solo tiene efecto con proveedores API que reportan uso de tokens (API de Anthropic principalmente).
